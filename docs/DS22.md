## Gerar os três pacotes

Na estação macOS, instalar Unity 6000.6.0f1 com os módulos Windows Build Support (Mono), Linux Build Support (Mono) e o suporte macOS. Python 3, Git e `ditto` são usados pelo gerador.

Depois de integrar as quatro cenas do DS-13:

```sh
python3 scripts/build_candidate.py \
  --unity /Applications/Unity/Hub/Editor/6000.6.0f1/Unity.app/Contents/MacOS/Unity \
  --version 0.1.0-rc.1 \
  --target all
```

Para gerar um alvo isolado, usar `--target windows`, `--target linux` ou `--target macos`. Saídas padrão: `Builds/Candidates/` e `Builds/Backup/`. É possível definir `--project`, `--output` e `--backup`.

O editor verifica a versão da Unity, a presença e a ordem das quatro cenas e o módulo do alvo. O build usa Mono, sem Development Build. A versão e o backend anteriores são restaurados ao terminar. O empacotador só aceita um relatório de sucesso correspondente à versão e à plataforma solicitadas.

Windows e macOS recebem ZIP; Linux recebe `.tar.gz`, preservando as permissões de execução. Os arquivos de diagnóstico que a Unity marca como não distribuíveis e o log bruto de compilação ficam fora do pacote. Os logs permanecem na pasta de build para revisão.

As instruções distribuídas vêm de `docs/EXECUCAO.md`; as limitações vêm de `docs/NOTAS_CANDIDATA.md`. Atualizar essas notas antes de gerar uma nova candidata.

## Validação do gerador

```sh
python3 -m unittest discover -s scripts/tests -v
```

Onze testes aprovados nesta máquina: integridade da reserva, conteúdo dos pacotes, permissões Linux, links do bundle macOS, versões inválidas, plataforma/versão incompatíveis, builds incompletas ou com erro, preservação de saídas anteriores e exclusão de diagnósticos.
